# 交互原型与核心逻辑

## 第一章核心互动：数据清洗消消乐
**设计目标**：让学生直观感受到代码指令（清洗工具）与“脏数据”消除的直接联系。
**UI 原型**：
- **左侧**：展示多张残缺或错误的“数据卡片”（如包含 `@#` 的名字、空缺的联系方式、重复的学生记录）。
- **右侧**：工具面板，提供写有 Pandas 方法的“代码胶囊”（如 `dropna()`, `fillna()`, `drop_duplicates()`）。
- **交互方式**：
  - 用户拖拽右侧的代码胶囊至左侧对应的不规则数据卡片上。
  - 若方法匹配正确（例如 `dropna()` 用于含有 `NaN` 的空数据卡片），触发 GSAP 消除动效，卡片变整洁。
**代码检测与 Pyodide 逻辑**：
- 前端记录用户的连线或拖拽对。当所有工具使用正确后，前端拼接完整的 Pandas 清洗代码。
- 将生成的 Python 脚本通过 Web Worker 发送给 Pyodide 执行。Pyodide 读取虚拟文件系统中的原始 CSV/Excel，运行用户的清洗脚本，返回清洗后的 DataFrame 的 `.head()`，展示在下方的“数据控制台”中。

## 第二章核心互动：可视化连连看
**设计目标**：强化图表类型（柱状图、折线图、散点图、饼图）与数据特征的匹配关系。
**UI 原型**：
- **左栏（数据需求侧）**：列出多个需要解决的现实问题（如“各比赛项目报名人数比较”、“某运动员心率随时间的变化”、“男女生在报名总人数中的比例”）。
- **右栏（图表侧）**：并列展示 ECharts 预渲染的图表微缩图（柱状图、折线图、饼图）。
- **交互方式**：
  - 用户点击左侧问题，然后连线至右侧的图表。
  - 连错触发 GSAP 抖动反馈；连对则锁定，并自动在中央生成对应的 Matplotlib 核心代码（如 `plt.bar()`, `plt.plot()`）。
**代码检测与 Pyodide 逻辑**：
- 用户的匹配动作更新 Vue 状态（Pinia）。
- 过关后，学生可以在网页终端中修改代码参数（如 `color='red'`），利用 Pyodide 执行。Pyodide 使用底层拦截将 Matplotlib 的输出转化为 base64 图片，并回显至前端预览区。

## 第三章核心互动：Blockly 积木拼装 GUI
**设计目标**：理解事件驱动和图形界面（GUI）的基本概念，降低手写 Tkinter 布局的门槛。
**UI 原型**：
- **左侧**：基于 Google Blockly 的可视化积木面板，提供 `窗口(Tk)`、`标签(Label)`、`按钮(Button)`、`文本框(Text)` 等组件积木。
- **右侧**：分上下两部分，上方为实时 UI 原型预览区（利用 HTML/CSS 模拟 Tkinter 组件呈现外观），下方为实时生成的 Python Tkinter 源代码。
- **交互方式**：
  - 用户拖拽积木块完成“添加窗口”并放入“生成图表按钮”。
  - 为按钮绑定事件（拼接“回调函数”积木）。
**逻辑实现**：
- 通过 Blockly 自定义 Python 生成器，将拼接的块转换为标准 Tkinter 代码。
- 由于浏览器内的 Pyodide 无法直接打开真实的系统原生桌面 GUI 窗口，前端通过拦截 Blockly 生成的代码，在 Vue 中利用 HTML/CSS 实时渲染对应的模拟窗口界面。
- 让学生点击网页上模拟生成的“选择文件”、“清洗数据”按钮，触发表单逻辑，体会“事件驱动”的回调函数原理。
